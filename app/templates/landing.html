What Beacon stores

{{ demo.beacon_id }}

A keyed hash of the address, the browser and {{ demo.site }}, under the salt for {{ demo.day }}. Change the person, the site or the day and this is a different number, because all three go into it.

{% if demo.salt_still_exists %}

That day’s salt still exists, so this can still be recomputed.

{% else %}

That day’s salt has been deleted. Nothing can reproduce this number now — not an attacker with the database, and not us.

{% endif %}

What a cookie stores

{{ demo.cookie_id }}

Assigned once and written to the device. It is not computed from the site or the day, so there is nothing for either to change. The same value follows this person to every site that sets it, for as long as they keep it.

Nothing here expires on its own.

No cookies, no banner

Visitors are recognised by a keyed hash of their address and browser, salted with a value that is generated fresh each day and deleted two days later. Once it is gone, nobody can reproduce the mapping — not an attacker with a stolen backup, and not us.

Reduced at the door

Query strings are dropped from URLs, referrers are cut to their host, and the address becomes a country code and is then discarded. There is no column in the database capable of holding an IP or a raw User-Agent.

Fast at any size

Counts are pre-aggregated on a daily grain, which the salt rotation makes exactly additive. A year of traffic renders in single-digit milliseconds instead of two seconds.
